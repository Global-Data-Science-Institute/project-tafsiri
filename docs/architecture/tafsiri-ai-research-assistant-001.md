# Tafsiri AI Research Assistant 001

The assistant is a provider-neutral proposal layer inside Data Studio. Its interface accepts an authorized immutable contribution snapshot plus workflow and returns structured suggestions; it has no tools for canonical writes, language registration, reviewer assignment or training. It never certifies language correctness.

The implemented adapters are a deterministic mock and an optional OpenAI Responses adapter. Mock processing requires no API key. OpenAI is off by default and requires server enablement/key/model, project enablement and explicit contribution consent. The adapter sends only contributor-supplied text fields, uses structured output, a 20-second timeout, 1,200 output-token cap and `store:false`, and rejects candidate strings absent from input evidence. No live provider calls were made; the HTTP transport is mocked in tests. `store:false` is not a claim of zero provider retention or permission to process real material. Unsupported providers fail closed. Consult the [official Responses contract](https://developers.openai.com/api/reference/resources/responses/methods/create) before changing the integration.

| Workflow | Offline MVP behavior / future boundary |
|---|---|
| Document assistance | Proposes metadata from contributor-supplied text and evidence references; raw document OCR/parsing is deferred and quarantine files are never executed |
| Contributor assistance | Identifies missing context/source/counterpart scope and asks targeted questions |
| Linguistic candidates | Returns uncertainty and requests qualified human input; no unsupported interpretation, morphology or translation |
| Quality assistance | Flags identical own/project-visible text, missing metadata and unresolved scope; possible transcription/contradiction judgments require evidence and remain proposals |
| Task preparation | Proposes an annotation task descriptor referencing the exact contribution revision; handoff remains blocked until authorized integration |

All outputs carry MACHINE_GENERATED and UNVERIFIED, adapter/model identity, prompt/configuration version, contribution ID/revision, elapsed time and workflow. The database reserves an attributed run after current authorization and quota checks; only the server completion RPC can store adapter results. It rechecks access, revision, withdrawal and external consent before publication. Limits are 20 requests per actor/day and 100 per project/day; failures consume admission quota. Replays never make a second provider call. Abandoned RUNNING requests require later operator reconciliation rather than automatic potentially billable retries. Suggestions remain separate from submitted originals and cannot confer rights.

Future providers must implement the same bounded contract, structured-output validation, timeout, size/token budget, daily/project limits, idempotent request records, cancellation, secret custody and redacted error handling. Admission must require current project AND contribution external-processing consent, permitted purpose, an approved provider/region/retention policy and a human-authorized evidence set. User text is untrusted data, never instructions to change policy or execute tools. API keys stay server-side; no training/retention setting is inferred from a provider name. Consent revoked during processing blocks publication and invokes the documented retention/deletion procedure.

No reliable language support means uncertainty or human input. A model must not invent native vocabulary, translate without evidence or treat its own outputs as human verification. Synthetic adapter success proves no model capability. Raw file OCR/document parsing and audio transcription are explicitly unsupported; contributors may supply authorized text or transcripts for assistance. Real external activation still requires provider retention/region/rights review and independent acceptance. Withdrawal cannot undo data already transmitted before revocation; no such transmission occurs in this milestone's tests.
