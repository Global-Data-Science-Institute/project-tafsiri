## File admission policy

All accepted files are nonempty and at most 5 MiB. Text must be valid UTF-8 without NUL. WAV is limited to RIFF/WAVE, one 16-byte PCM format chunk followed by one nonempty data chunk, 1–2 channels, 8/16/24/32 bits, 8–96 kHz and at most 300 seconds. Declared RIFF/chunk lengths, padding, block alignment, byte rate and frame lengths must agree. Unknown chunks and non-PCM encodings fail closed.

PDF validation uses qpdf 12.2.0 in the tested Debian image. `--check` must exit zero; warnings/recovery, failures and crashes reject. JSON version 2 exposes decoded dictionary names and indirect/unreferenced objects. Encryption, actions, forms, annotations, attachments, external stream references and interactive content are disallowed. Limits are 100 pages, 10,000 objects, 100,000 traversed values, 8 MiB parser output and 10 seconds per parser invocation. qpdf is a maintained structural parser, **not a complete ISO conformance checker, renderer or guarantee against every viewer vulnerability**. The conservative policy may reject otherwise usable PDFs. No downstream rendering/extraction is enabled by this task. See [qpdf CLI](https://qpdf.readthedocs.io/en/stable/cli.html) and [JSON object representation](https://qpdf.readthedocs.io/en/stable/json.html).

WebM is explicitly unsupported for admission. Both generated valid WebM silence and malformed EBML magic remain quarantined with UNSUPPORTED_FORMAT. Capture/storage functionality is retained, and the UI explains the restriction. A later validator needs its own review; no full WebM validation is claimed.

Only structure-valid files reach malware scanning. Only a successful scan can return ADMITTED/CLEAN. Invalid/unsupported formats, limits, parser failures and signature failures return ERROR; malware returns INFECTED. Internal codes distinguish INVALID_FORMAT, UNSUPPORTED_FORMAT, MALWARE_DETECTED, SCANNER_UNAVAILABLE, SCANNER_TIMEOUT and SIGNATURE_VERIFICATION_FAILURE, plus parser/limit codes. Bounded codes and verified daily metadata are retained in the existing scan receipt; private contents and executable output are not logged. ERROR retains the existing five-minute retry behavior, so malformed files can repeat until withdrawn/deleted; queue monitoring remains required. Mock results remain MOCK_CLEAN in the database and are not real antivirus evidence.

## Signature verification and activation

The reviewed engine profile is ClamAV 1.4.7 / functionality level 217. The sigtool executable must report the same version. Only `main.cvd`, `daily.cvd` and `bytecode.cvd` are loaded, each verified using `sigtool --info`. Missing files, symlinks, unexpected database formats, oversized containers and unverifiable databases reject. The installed 1.4.7 implementation verifies the CVD signature/payload and compares outer version, signature count, functionality level and epoch timestamp against the internal `.info` metadata. Freshness uses that checked epoch, not the display date or filesystem mtime. The forged-header regression tests this distinction. See the [ClamAV verifier implementation](https://github.com/Cisco-Talos/clamav/blob/clamav-1.4.7/libclamav/cvd.c), [sigtool verification](https://github.com/Cisco-Talos/clamav/blob/clamav-1.4.7/sigtool/sigtool.c), and [engine functionality levels](https://docs.clamav.net/appendix/FunctionalityLevels.html).

`STUDIO_SIGNATURE_MAX_AGE_HOURS` is mandatory, positive and capped at 48. Daily signatures enforce the rolling age; main and bytecode are signed static components with independent release schedules, so they are integrity/version checked without imposing a daily age on their older builds. Timestamps more than five minutes in the future reject. Correct host time is an operational dependency. CLD/CUD and newer detached-signature formats are unsupported; the updater requests full CVDs with `ScriptedUpdates no`. Supporting them requires format-specific verification and tests, not renaming files.

`studio-signature-update.mjs` downloads into a unique unpublished generation, tests/verifies all databases, makes files read-only, then atomically renames a temporary symlink to `current`. The scanner resolves `current` once and passes the exact three verified generation paths to ClamAV. The updater never mutates published generations, and retains previous generations for in-flight readers. A separate OS updater identity must own the root; the scanner gets read-only mounts. Administrative filesystem access remains trusted. A killed updater leaves a lock requiring operator inspection/recovery; failed generations cannot become current. Generation garbage collection and power-loss durability procedures need operations review; an interrupted process test is not a power-loss rehearsal.

Worker configuration additionally requires absolute `STUDIO_CLAMSCAN_PATH`, `STUDIO_SIGTOOL_PATH`, `STUDIO_QPDF_PATH`, and `STUDIO_CLAMAV_DATABASE` pointing at `current`. Updater configuration adds `STUDIO_FRESHCLAM_PATH` and `STUDIO_SIGNATURE_ROOT`; it must receive no Supabase credentials. Unknown engine versions fail closed until reviewed. Every new worker process re-verifies signatures; no mtime cache or unsigned local attestation can admit files.

## Intentional privilege changes

The local pre-change catalog showed anon/authenticated grants on all 16 identified tables, all without RLS; the six views ran as owner. Supabase exposes `public` through PostgREST independently of Vercel. Repository application consumers use Studio RPC intake and Reviewer Portal assignments; raw dictionaries feed privileged research/reconciliation tooling. No repository application consumer requires anonymous `submissions` writes. External consumers are not assumed to be authorized merely because a historical grant exists. Their owners must review the explicit changes before hosted use.

| --- | --- | --- |
| `bible_books`, `bible_english_verses`, `bible_luhya_verses` | No SELECT or writes; RLS enabled | Imported corpus without a reviewed public publication/rights boundary. Privileged research access preserved |
| `knowledge_base_entries`, `luhya_dict`, `luhya_dictionary`, `luhya_kb`, `luhya_proverbs`, `proverbs`, `translations` | No SELECT or writes; RLS enabled; two dictionary sequences also revoked | Raw source/translation content and provenance may contain restricted material; legacy `is_approved` defaults are not publication authorization |

| `dialect_aliases`, `pronouns`, `pronoun_examples` | Read only with registry-linked predicates | Public dialect/reference consumers and pronoun views retained. No broad new `USING (true)` policy |
| `languages`, `dialects`, `cultural_contexts`, `dialect_variants`, `dictionary_entries`, `grammar_patterns`, `prompts`, `usage_examples`, `verb_forms`, `word_relationships` | Existing explicitly public reads preserved; unnecessary write ACLs revoked | These already have public reference policies. No private partner material may be copied into them |
| `pronunciations` | Selected linguistic columns readable; `speaker_info` denied; writes denied | Public audio/reference views remain functional without exposing speaker identity via SELECT * |
| `word_details`, `cultural_terms`, `language_words`, `pronoun_comparison`, `pronoun_details`, `dialect_comparisons` | SELECT only, `security_invoker=true` | Denied base access is denied through the view; no owner privilege bypass |

| Reviewer helper functions | Authenticated invocation preserved, anonymous invocation revoked | Existing assignment predicates retained; trigger functions have no ordinary-client EXECUTE |

The migration does not add an anonymous intake endpoint: none is needed by the current application. Legitimate contributions continue through authenticated, consent-bound Studio or existing owner-scoped untrusted intake. Service-role access remains broad and is a residual risk, not solved by RLS.

- Python: 189 passed. Frontend: 68 passed; TypeScript, ESLint and production build passed.
- Database backup/restore and separate private Storage checksum/anonymous-denial rehearsal passed. SQL lint found no schema errors. [Advisor summary](advisors-remediation.json): zero errors; 18 pre-existing warnings (14 overlapping-policy role expansions, three auth initialization plans, vector in public). Counts depend on local roles; this is not a hosted advisor claim.
- [Real scanner matrix](remediation-scanner-results.json) records 33 cases, qpdf/ClamAV versions, verified signature metadata and individual outcomes. Tests include original malformed files, valid PDF/WAV, encoded/indirect actions, encryption, WAV metadata/length/duration, valid and malformed WebM rejection, EICAR, process deadlines, size limits, corrupted/unverifiable/stale databases, forged timestamp, unsupported format/version, interrupted activation, fresh worker process and concurrent scans.
- Actual worker/Auth/Storage integration covers valid text, EICAR, hash mismatch and both original malformed documents. Pending, infected and ERROR files are unreadable; only CLEAN is downloadable.

The scanner runtime has no network, a read-only root, dropped capabilities, no-new-privileges, UID/GID 65532, 6 GiB memory, two CPUs, 64 PIDs and 2 GiB noexec/nosuid temporary space. Only the Studio library and test source directories are mounted read-only; no workspace root, `.studio-local`, application environment file or credentials are mounted. The larger memory/temp allowance accommodates copied signature generations and concurrent tests; it supersedes the old four-GiB test recipe and is not a production capacity claim. FFmpeg only generates synthetic WebM silence in the test image.

The package SHA-256 remains checked against the pinned 1.4.7 download; detached package GPG verification remains outside this evidence. Debian qpdf/FFmpeg packages and fresh signatures can advance on rebuild; record actual image digest/version rather than claiming reproducible byte identity. Freshclam's build-time missing-clamd notification is nonfatal because this harness uses clamscan, not clamd; database verification/load tests pass. The atomic activation tests use real signed CVD copies in a network-disabled sandbox; they do not certify a hosted timer or network recovery.

CI adds a real scanner job and local SQL/PostgREST/advisor checks. All prior research, portal, database replay/concurrency and Studio jobs remain. Exact candidate check status belongs to the draft PR; a green run is not independent security approval.
